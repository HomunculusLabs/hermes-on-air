# Build live on stream

Use this guide to build in public steps with selected text and your own narration.

In your local owner agent, say: **“Build a banana phone synth live.”** If you do not name a
folder, the agent proposes a new project subfolder of the current working directory for you to
confirm or replace. The agent shows selected public code, real test output and a short step rail
in the work view, with the optional 3D scene inset (or large if you ask). It makes small changes
and leaves the result visible until you say to clear it. Work view is authored text, not a screen
or terminal capture; review the actual OBS preview and audio.

The builder is **your agent**, not the co-host. The co-host is a separate stage and can receive
host lines through relayed notes, not direct access to the project. **Current limitation:** the
relay tool permits only your own requested words, faithfully passed along; it does not authorize
the builder to invent milestone notes. For narration, supply exact short public lines and ask
for them to be relayed; a one-sentence build brief alone does not produce autonomous narration.
Queued does not mean spoken. Host turns must be enabled and the stage ready. In approval mode
you approve guarded replies; in autonomous mode model relays are refused unless you explicitly
opt in, after which guarded replies may air without your approval. Current speech, generation,
approvals and the settling window can add delay; there is no latency guarantee. See [Host
turns](host-turns.md).

You retain control of arming, line approvals, privacy, mute, and going live. Stop or request
privacy or off air at any time: the agent stops and clears the work view, but check OBS as this is
not a whole-program privacy cut. Never share credentials or private content. The optional scene
and owned OBS sources must be ready, and the presentation follows the configured overlay's safety
state. Work view and layout limits are in [Work view](work-share.md) and [Views](views.md).
